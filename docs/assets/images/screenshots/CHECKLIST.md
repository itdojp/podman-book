# スクリーンショット候補チェックリスト（章別）

本書本文に差し込む「操作画面キャプチャ（ターミナル/GUI/Web UI 等）」の候補一覧です。
Issue #180 の作業用チェックリストとして運用し、実画像はここでは追加しません（候補一覧整備まで）。

- 章タイトルは改訂で変更され得るため、本ファイルでは `chapterXX`（ディレクトリ名）を主キーとして管理します。
- 格納先/命名/マスキング/キャプションの方針は `docs/assets/images/screenshots/README.md` を参照してください。

## 記法

- **[P0]**: 本文理解に直結するため優先度が高い
- **[P1]**: 余力があれば追加する
- 各項目は「画面（種別）」「前提（撮影前の状態）」「撮影ポイント（読者に見せたい情報）」を併記します。

## 共通（複数章で再利用しやすい）

- [ ] **[P0]** `podman --version` / `podman info`（実行環境の前提が分かるもの）
  - 画面: ターミナル
  - 前提: Podman インストール済み。可能なら rootless ユーザで実行（採用した方式はキャプションで明記）。
  - 撮影ポイント: rootless/ストレージ/ネットワーク等の前提が判別できる範囲を同一画面に収める（必要なら `grep`/`jq` で絞り込み）。

- [ ] **[P0]** `podman ps` / `podman images` / `podman volume ls` / `podman network ls` / `podman pod ps`（一覧の読み方が分かる状態）
  - 画面: ターミナル
  - 前提: 出力が空にならないよう、例示用に最低1件のリソース（コンテナ/イメージ/ボリューム/ネットワーク/Pod）を用意する。
  - 撮影ポイント: 本文で解説する列（例: STATUS/PORTS/SIZE 等）が視認でき、秘匿情報が含まれないこと。

- [ ] **[P1]** 典型的なエラー例（権限/SELinux/AppArmor/名前空間等）と、解消後の再実行
  - 画面: ターミナル
  - 前提: 再現用の一時環境（または検証VM）で実施し、影響が残らないことを確認する。
  - 撮影ポイント: 「どこで詰まりやすいか」と「復旧後に何が変わるか」が対比できるよう、失敗→解消→成功を同一節で揃える。

  - 画面: ターミナル

  - 撮影ポイント: `dockerd` の常駐有無や、Podman がデーモンレスであることが読み取れる範囲を示す。

- [ ] **[P1]** `podman stats --no-stream`（メトリクスの見方）
  - 画面: ターミナル
  - 前提: リソース使用が観測できるよう、対象コンテナを起動しておく。
  - 撮影ポイント: CPU/MEM/NET IO 等の主要列が視認できること。

## chapter02（インストール/初期設定）

- [ ] **[P0]** Linux: インストール → `podman run --rm hello-world`（初回成功）
  - 画面: ターミナル
  - 前提: 対象ディストリで Podman を未導入の状態から実施（既存環境の場合は検証用VMを推奨）。

- [ ] **[P0]** macOS: `podman machine init/start` と `podman info`（machine 稼働）
  - 画面: ターミナル
  - 前提: macOS に Podman を導入済み。machine が未作成なら `init` から実施する。
  - 撮影ポイント: machine の起動状態と、接続先がローカルVMであることが判別できる情報。

- [ ] **[P1]** Windows: PowerShell での前提確認（WSL2 有効化等）
  - 画面: PowerShell
  - 前提: Windows 環境。個人情報（ユーザ名/パス/組織名）が混入しないように配慮する。
  - 撮影ポイント: 以後の手順に必要な前提（WSL2/仮想化機能/ディストリビューション等）が確認できること。
